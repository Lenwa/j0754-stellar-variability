Native coordinate and wavelength recipe
Compute 0-based target xcut,ycut from the IMAGE celestial WCS. For IRSA cutouts, xorig=1+xcut-CRPIX1A, yorig=1+ycut-CRPIX2A. The +1 is essential. All relevant zone centers are 0-based. Select the ePSF row with minimum squared distance from (xorig,yorig) to (XCENTER,YCENTER), as in the official tutorial. Do not use the old 11x11 PSF-zone indices for the ePSF table.
The official forced-photometry source assigns CWAVE[yidx,xidx] and CBAND[yidx,xidx] at the nearest integer detector pixel using world_to_array_index. A subpixel interpolation is a separately declared refinement, not the exact native recipe. Record original floating coordinates, integer coordinates and chosen calibration files with each point.

Critical ePSF rendering distinction
The new ePSF is already pixel-convolved and predicts detector pixel values for an arbitrary subpixel source phase. The official tutorial prose uses terms such as downsample/integrate, but its executable reference recipe constructs photutils.psf.ImagePSF(data=EPSF,oversampling=(5,5)), evaluates it on native detector pixel centers at the true source centroid, and normalizes the rendered 11x11 stamp by its sum. Follow that actual evaluation recipe. An additional 5x5 box integration of the new ePSF would convolve the pixel response again. The older QR2 optical PSF uses a different integrate-and-downsample recipe and must not be confused with the ePSF.
The ePSF's origin is the central oversampled sample, (16,16). A dependency-free bilinear approximation samples EPSF at u=16+5*(x-x0), v=16+5*(y-y0), with zero outside the 33x33 support, then normalizes the native stamp to sum=1. Photutils ImagePSF uses spline interpolation; therefore bilinear results are a declared approximation. Do not fit the raw oversampled cube directly as a native stamp. Do not omit normalization: raw native samples sum near 1/25. Do not renormalize only the unmasked fit pixels; normalize the full rendered PSF, then mask bad pixels for fitting. Masked pixels are missing information, not a change in total source flux.

Flux and uncertainty recipe
For a native unit-sum point-source template P_i and local surface-brightness background b_i, model IMAGE_i = A*P_i + b_i, in MJy/sr. With background fixed, A=sum(P_i*(IMAGE_i-b_i)/V_i)/sum(P_i^2/V_i), Var(A)=1/sum(P_i^2/V_i), using VARIANCE V_i in (MJy/sr)^2. For joint constant/plane background, solve the weighted linear design matrix [P,1] or [P,1,x,y]; covariance is inverse(X^T W X). These are local linear estimators, not proof of the complete SSDC pipeline implementation.
Official source uses invvar=1/VARIANCE and converts its unit-sum-template amplitude using the local pixel solid-angle map at the rounded source centroid. Fnu[uJy]=A[MJy/sr]*Omega[arcsec2]*1e12/(206264.80624709636^2). Apply the same factor to sigma_A. No extra oversampling factor belongs in this conversion after a unit-sum native template has been fitted. A pixelwise alternative first converts IMAGE and variance to uJy and uJy^2 using each pixel area before fitting; declare this difference if used.
Uncertainty above is conditional on position/template/background and independent pixel noise; PSF mismatch, residual calibration, astrometry, background structure, crowding and correlations are additional uncertainties. Reporting covariance errors alone does not measure those effects.

Background and flags
IMAGE includes zodiacal light. ZODI is a model that has not been subtracted. The native Spectrophotometry Tool explicitly does not use ZODI: it estimates and removes a local background, masking known-source pixels, before forced photometry. Local empirical background may include zodiacal light and additional diffuse signal. If subtracting ZODI, still fit residual background and do not subtract the same background twice. Save fitted/annular backgrounds and inspect wavelength discontinuities.
SOURCE bit21 (2097152) means mapped to a known source; it is nominal for source pixels and must not be masked out of the source fit. Use it for excluding source pixels in a background estimator. FULLSAMPLE bit12 is also informational. Check finite positive variance and finite IMAGE in all fits.
Native tool ignores pixels with SUR_ERROR2, NONFUNC6, MISSING_DATA9, HOT10, COLD11, NONLINEAR15, PERSIST17, BLOOM26, SNOWBALL27, HALO28, SATELLITE_HALO29. Its output also warns on harmful bits within radius2.5 native pixels: TRANSIENT0, OVERFLOW1, DICHROIC7, CROSSTALK20, GHOST22/GHOST_FPA23/GHOST_EXT24, STREAK25, plus ignored bits. OUTLIER19, VAR_UNDER16, PERSIST_UNK18 require explicit handling/review rather than assuming unflagged noise. Conservative extra masking is reasonable but differs from native behavior. DICHROIC measurements near the D3/D4 boundary have known imperfect calibration and deserve exclusion or explicit skepticism. OVERFLOW/NONLINEAR/bloom indicate saturation-related unreliability.

Validation performed
D6 sample calibration validation is saved in D6_sample_calibration_validation.json: cutout target=(7.4644541618,7.3477603971), parent=(1135.4644541618,420.3477603971), nearest ePSF row95 centered at (1116.642822,436.642853). Rounded-pixel CWAVE=4.86862659454 um, CBAND=0.0372762829065 um; Omega=37.7645606995 arcsec2, conversion=887.634493800 uJy/(MJy/sr amplitude). Stored ePSF sum=1. Native bilinear phase-sampled raw sum=.03980563; normalized sum=1 and effective noise area=5.76445 native pixels for target phase. NEFF_MEAN=4.98276 is a zone/phase aggregate, so it need not equal one rendered phase. Integer and half-pixel phases have different noise areas, confirming why subpixel phase matters.
Recommended extractor checks: inject a known amplitude on the rendered native template plus constant/gradient background, recover it at integer and fractional phases; test finite bad-pixel masks without renormalizing the good-pixel template; verify recovered flux conversion with local area. Compare ePSF fits, background alternatives, aperture sums with explicit encircled-energy corrections, and free-centroid versus fixed-astrometry sensitivity. An injection using the same renderer checks algebra and bookkeeping but cannot validate the renderer against physical data. An independent native server result or external standard is needed for that.

Known limitations
QR2 headers before 31 March 2026 had an old-PSF coordinate-description error causing location-dependent photometry errors up to about +/-5%. Corrected VERSION6.4 through6.5.5 carry +psffix1;6.5.6 onward were unaffected. New ePSF table selection avoids reliance on the old PSF headers. QR3 flux-correction calibrations exist but are not QR2 calibration products; do not apply them blindly to QR2. No globally validated absolute systematic uncertainty for this local extraction has been established by this audit. Small error bars, smooth spectra or synthetic recovery alone must not be treated as calibration validation. Crowded neighbors need simultaneous source modeling; SOURCE flags alone do not establish an isolated point source. Per-season spectra are not necessarily simultaneous and comparisons require matching wavelength response and flags.

Native independently endorsed extraction route
GUI: https://irsa.ipac.caltech.edu/applications/spherex/
Select Spectrophotometry, Point Source, a single target at the stated decimal-degree position, all bands, no deep fields needed. Send to Background and inspect Job Monitor. Completed results include flux/error in uJy, wavelength/width in um, pixel flags, background, fit_ql and exposure provenance. For223 images the documentation's rough estimate is1.67*N+50 seconds (~422 seconds), subject to queue/load. Save completed spectrum/table immediately. No documented spectrophotometry REST API was found in the inspected archive documentation or public Firefly source tree; do not guess private endpoints. This audit did not submit a GUI extraction job.
